    02Debrief: why this order

    1. Data

      Download the raw Hard Hat dataset: 5,000 construction-site photos, 3 classes (helmet, head, person), labelled in Pascal VOC.

    2. Convert

      Ultralytics reads YOLO format, so every VOC .xml becomes a .txt with one normalised line per box, plus a data.yaml. Then draw the converted boxes back onto the images to check them.

    3. Fine-tune

      Start from a COCO-pretrained yolo11s and call train(). Because data.yaml lists 3 classes, the head is rebuilt for them automatically.

    4. Thresholds

      Two knobs decide which boxes you keep: confidence (is this box worth reporting?) and NMS IoU (are these two boxes the same object?). Sweep them on the validation split and pick an operating point.

    5. Evaluate

      On the held-out test split: mAP50 and mAP50-95 (measured at confidence ≈ 0.001), then the error analysis at your chosen thresholds. Why is each false positive wrong, and which object sizes get missed?

    6. Inference

      model.predict() on images and video, using the deployment thresholds, and measure the FPS.

    Where did Day 3's Freeze and Replace go?

    They're still there, but Ultralytics does them for you inside train(). It rebuilds the detection head for our 3 classes and transfers every pretrained weight that still fits.

    Why Thresholds before Evaluate?

    The error analysis counts true and false positives, and those depend on which boxes survive the thresholds. So you choose them first, on validation data, and then report on the test set once. The mAP number itself is measured at a near-zero confidence, because mAP integrates the whole precision–recall curve and a high threshold would cut it short.
