    02Debrief: why this order

    1. Understand the data

      You can't judge any backbone until you know your classes, image size, balance and quirks (Days 1–2).

    2. Choose candidate backbones

      Match the pretraining data, the architecture and the size to the task (Exercise 1).

    3. Freeze the backbone

      param.requires_grad = False. The pretrained features are locked so the first, noisy gradient steps can't wreck them.

    4. Replace the classifier

      The ImageNet head predicts 1,000 classes. Swap it for a fresh nn.Linear(2048, 10). A new layer is created with requires_grad = True, so it's the only thing that trains.

    5. Train the classifier

      A linear probe: only the new head learns. Later in the lab we also unfreeze Stage 4 with a 10× smaller learning rate.

    6. Evaluate

      model.eval() on the held-out test set: classification report, confusion matrix, most confident mistakes.

    Freeze ↔ Replace: does the order really matter?

    In §0.3–0.4 we freeze all parameters first and then replace the head, so the new head starts out trainable.

    Later in the notebook we replace first and then freeze only model.base_model. That's correct too. What matters is that the new head ends up trainable. If you replaced the head and then froze model.parameters(), you'd freeze the new head as well, and nothing would learn.
