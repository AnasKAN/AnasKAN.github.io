0.2 · CHOOSING OUR PRETRAINED MODEL

Pick the backbone. Then defend it.

The pretrained model (aka backbone) acts as a feature extractor, so our model doesn't have to learn everything about our data from zero. But that only helps if we pick the right one. Six candidates, one real-world job. Which would you ship?

01The mission

USE CASE

A startup is building a phone app. When the user points the camera at something, the app must answer one question: is there a human face in this image, yes or no?

We have a labelled dataset of face / no-face images, and we will fine-tune a pretrained backbone on it. The catch: the finished model has to run on the phone itself.

Runs on the deviceNo internet, no cloud GPU. Everything happens on the phone.
Limited memory & batteryIt shares a mid-range phone with every other app.
Has to feel instantUsers won't wait seconds for a yes / no.
Has to be rightA fast model that can't recognise a face is useless.

05Debrief

The pick: Backbone D (31 M parameters, pretrained on MS COCO)

It's the only candidate that has seen people. "Person" is the most common category in COCO's everyday scenes, so D's features already respond to heads, skin and faces. At 31 M parameters (~124 MB in FP32, ~31 MB once quantised to INT8) it still fits on a phone. The smaller models are cheaper but learned the wrong things. The bigger ones are too heavy for the device, and their pretraining data has no faces either.

1 · Data first

A backbone only extracts useful features if its pretraining images look like yours. Leaves, galaxies and satellite tiles teach filters that rarely fire on a face.

2 · Then size

Quick memory estimate: params × 4 bytes for FP32, × 2 for FP16, × 1 for INT8. 632 M params ≈ 2.5 GB in FP32. That won't run on a phone.

3 · Smallest ≠ best

A 15 M model that has never seen a face can need more data and more training than a 31 M model that has. Data mismatch costs you accuracy. Extra parameters cost you memory.

4 · Big model, tiny data?

Be suspicious of a 305 M model pretrained on ~8 K flower photos. That's a lot of parameters for very little data, so it has likely memorised its training set rather than learned general features.
